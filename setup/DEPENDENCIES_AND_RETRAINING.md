# Dependencies and model-update paths

This is the dependency map for the portable Desktop clone, updated 11 November
2026. It covers the deployed paper engines and the imported V2 and
VolPred research source. Historical data and service credentials are external
to Git; their absence does not prevent cloning or offline model preflight.

## Source and Python packages

| Component | Code and saved models in the clone | Python packages |
|---|---|---|
| Scheduled IVRV, PCR, 43Weeks and older standalone engines | `pipelines/families/` | Python 3.13 and `pipelines/requirements.txt` in root `.venv` (NumPy 2.5.2, pandas 2.3.3, scikit-learn 1.9.0, SciPy 1.18.1, joblib 1.5.3, LightGBM 4.7.0, XGBoost 3.4.1, DuckDB 1.5.6, NGBoost, PyYAML, matplotlib, statsmodels, psycopg, hmmlearn, pytest). | VolPred RV/hybrid research, separate spot app and DTE paper intents | `research/volpred/` | Separate ignored `.venv-volpred` from `requirements-vol-research.txt`: pandas 3.0.5, NumPy 2.5.2, scikit-learn 1.9.0, SciPy 1.18.1, DuckDB 1.5.6, joblib 1.5.3, LightGBM 4.7.0, matplotlib 3.11.1 and pytest 9.1.1. |

Run `setup/setup.ps1` first, then `setup/setup_research.ps1` if retraining is
needed. `pip check` passed in both environments on the source PC. The two
environments are separate because VolPred's frozen tests require pandas 3
timestamp precision, while the deployed inference environment pins pandas 2.
The target is Windows with Python 3.13 and access to PyPI or a wheel cache.
The Windows LZO decoder DLL is already tracked. Node.js is used for the
dashboard health test script, not for serving the paper dashboard. The older
spot/IV engine can optionally read contracts from PostgreSQL; its missing
model packages still block that engine before a live start.

## Raw data directory

The principal V2 and VolPred builders use these raw files. On this PC they are
in `E:\v2\data`. Put one copy on the destination's data drive
and run `setup/link_research_raw.ps1 -RawDataDirectory <path>` to make ignored
`research/v2/data/` and `research/volpred/data/raw/`
junctions to it. The junctions are local setup, not ZIP/Git contents.

| File | Size | Main use |
|---|---:|---|
| `icharts_option_banknifty.csv` | 15,445.2 MiB | Full fixed-strike exits, 43Weeks full chain and VolPred structure research |
| `icharts_option_banknifty_monthly_atm_5strikes.csv` | 743.3 MiB | V2 IVRV feature builders, 43Weeks and PCR training |
| `icharts_option_banknifty_monthly_atm_up_to_5strikes.csv` | 825.9 MiB | Rising-RV route and VolPred five-strike/DTE research |
| `icharts_option_banknifty_monthly_atm.csv` | 174.8 MiB | VolPred ATM IV/RV research panel |
| `icharts_banknifty_spot_1min.csv` | 28.0 MiB | V2 and VolPred spot/RV features |

The files above are **not** needed for a fresh scheduled IVRV paper session.
That session needs a daily FO contract master from the configured ERP service,
`ERP_AUTH_TOKEN`, and access to the FO/CM multicast feed. The independent
RV/hybrid paper engine needs a current FO master as well. The VolPred spot app
needs an updating one-minute spot CSV/HTTP source. None of these live feeds,
services, or credentials is in Git.

Many smaller derived panels can be regenerated by the copied feature builders,
but the full raw-to-model chain still needs validation before relying on it
for model updates. The expanded-hybrid retrain reached its 2023 selection gate
and stopped: the newly rebuilt entry-safe panel had no candidate meeting both
its 40-day minimum and positive-net requirement. The saved hybrid model remains
usable for inference; retraining it requires reconciling the historical panel
and selection rules. `setup/prepare_v2_training_configs.py`
accepts the original V2 `research/` directory at any location and writes four
ignored YAML configs containing its real feature paths. The raw CSVs can stay
on a data drive; they do not need to be copied into the repo.

For a fresh V2 rebuild, run these commands from the extracted repository root
after linking the raw directory. They write feature tables under ignored
`research/v2/research/*/artifacts/`; allow sufficient disk space for
the tables listed above. The fixed-strike IV builder supports `--max-days 2`
for a small input check before a full run.

```powershell
& '.venv\Scripts\python.exe' research/v2/research/combined_atm_iv_rv_convergence_v2/build_features.py --config research/v2/research/combined_atm_iv_rv_convergence_v2/config.yaml
& '.venv\Scripts\python.exe' research/v2/research/combined_atm_iv_rv_convergence_v2/repair_labels_fullchain.py
& '.venv\Scripts\python.exe' research/v2/research/fixed_strike_iv_rv_convergence/build_features.py --config research/v2/research/fixed_strike_iv_rv_convergence/config.yaml
& '.venv\Scripts\python.exe' research/v2/research/fixed_strike_iv_120m/run_pipeline.py all --config research/v2/research/fixed_strike_iv_120m/config.yaml
& '.venv\Scripts\python.exe' setup/prepare_v2_training_configs.py --feature-root research/v2/research
```

The combined-IV/RV and fixed-strike forward-RV builders completed on the full
raw inputs; both feature CSVs and manifests matched the original artifacts
byte-for-byte. The fixed-strike call/put-IV builder was exercised for two days
and passed its label/leakage audit. Its trainer completed a small end-to-end
run; the full data candidate search was stopped after three call-side model
families because of its compute cost.
Run `setup/validate_research.ps1` after installation and before retraining.

## Missing assets and model promotion

The older `standalone/main.py` engine still lacks four complete model
packages (`legacy_spot_iv/spot`, `iv`, `pnl`, `hmm`). They were absent on this
PC; their last-known paths and restore locations are in
[`legacy_spot_iv/README.md`](<../pipelines/families/ivrv/standalone/models/legacy_spot_iv/README.md>).
Its contracts can come from a current FO master or configured PostgreSQL.

Training outputs should remain under ignored `runtime/` or VolPred `outputs/`.
After retraining, inspect metrics and feature contracts, compare the selected
artifact with the deployed model, and rerun `setup/voltr.py preflight` and a
historical paper replay before deliberately promoting a model into
`pipelines/families/`. The source import and validation runs did not
change the deployed model bytes or live paper behavior.
